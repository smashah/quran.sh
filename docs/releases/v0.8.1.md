# quran.sh v0.8.1 — the immersive reader, made real

This patch brings the shipped terminal experience up to the standard of the v0.8 design study. Study, related hadith, and follow-play now have distinct task-focused compositions instead of sharing a cramped reader-plus-sidebar layout.

![quran.sh v0.8.1 immersive reader](https://github.com/smashah/quran.sh/releases/download/v0.8.1/quran-v0.8.1-immersive.gif)

[Watch the full terminal session](https://github.com/smashah/quran.sh/releases/download/v0.8.1/quran-v0.8.1-immersive.mp4)

The preview records the real `ImmersiveApp` through OpenTUI's live ANSI renderer in a PTY. Only provider responses and the playback clock are deterministic fixtures; the layout, keyboard interactions, RTL Arabic, scrolling, and playback state are the application itself.

## What changed

- Study is now a full responsive workspace. The ayah and translation remain visible in a context card while attributed commentary gets a bounded scrollable reading pane.
- Related hadith uses the same responsive model, with the ayah's context separated from bilingual narration text, collection identity, citation, and provenance.
- Follow-play now shows preparation or buffering, the verified active word, elapsed and total time, progress, and the next-ayah preload state.
- The reader keeps one stable centered ayah surface, Learn mode exposes transliteration, and the shorter footer no longer wraps controls through the reading area.
- At 88 columns the content stays in a useful split; smaller terminals stack it. Empty optional rows and raw policy URLs no longer consume the viewport.
- The release capture no longer reconstructs browser elements from OpenTUI's snapshot spans. That API displaced Quranic combining marks even though the live renderer emitted them correctly, so the preview now records the real PTY output.

OpenTUI's released cell text still cannot assign a larger font size to only the Arabic region. quran.sh gives the ayah more space, weight, and contrast in the normal terminal reader; genuinely scaled glyphs remain an opt-in graphics/Three concern rather than a simulated terminal feature.
