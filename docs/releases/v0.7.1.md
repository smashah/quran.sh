# quran.sh v0.7.1 — playback that completes the journey

This patch turns optional playback and spatial rendering into complete user flows. Pressing `p` without an installed recitation pack now offers a verified public Alafasy streaming index, while WebGPU setup is corrected and every unsupported machine has an immediate terminal-only visual fallback.

![quran.sh v0.7.1 dialogs and WebGPU probe](https://github.com/smashah/quran.sh/releases/download/v0.7.1/quran-v0.7.1-dialogs.gif)

## Highlights

- The download dialog identifies Mishary Rashid Alafasy and Al Quran Cloud / Islamic Network, explains that the ~607 KiB pack is an index rather than bundled audio, and records the source terms and attribution with the installed pack. Its versioned [resource release](https://github.com/smashah/quran.sh/releases/tag/resource-packs-v1) is independent of the application tag, and the application pins both asset hashes rather than trusting a replaceable remote manifest.
- Acquisition is deferred until confirmation, streamed with strict byte ceilings, restricted to HTTPS, pinned to the requested identity, checksum-verified, indexed, and atomically promoted. A failed download offers retry and the same operation is available as `quran resources install starter-audio`.
- Remote playback asks separately for network consent, names the provider and exact media host, and remembers approval only for that provider+origin because the CDN sees the request; quran.sh sends no listening history or telemetry. Playback stays at ayah level until a compatible pack contributes verified word timings.
- The WebGPU capability probe now calls `bun-webgpu`'s required `setupGlobals()` first. `quran doctor --gpu` performs an explicit live probe and gives macOS, Linux, Windows, missing-package, and unsupported-architecture guidance.
- Spatial mode now visibly frames the ordinary Arabic reader with responsive nested arches and stars without moving or rasterizing the text. A WebGPU failure opens a dialog with retry and a generated terminal-cell arch fallback, so the same experience remains usable without native graphics support.
- The accompanying Quran.com source audit maps its strong reader ideas to public/open sources, official credentialed APIs, private account data, and frontend-only internals before future study features are built.

The release passes strict TypeScript, the full Bun test suite, the deferred-import graph check, source and standalone builds, and macOS/Linux/Windows smoke paths. The default reader still performs no pack, audio, image, microphone, model, or GPU work at startup.
